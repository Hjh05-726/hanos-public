# 故障处理、停用与卸载

以下操作面向桌面安装。先保留 `doctor` 的错误代码，反馈时删除用户名、绝对路径和笔记正文。

## 第一步：确认版本和安装

在你下载的 HanOS 源码目录执行：

```bash
python3 install.py --version
python3 install.py --doctor
```

如果安装时指定过 `--home`，自检时使用同一个值。源码版本和已安装版本可能不同；未重新运行安装器时，不要假定升级已经生效。

| 现象 | 检查与处理 |
| --- | --- |
| 客户端找不到 HanOS | 先确认所选适配器已安装，再开启新会话或按客户端文档重新加载 Skill。仅复制本仓库不等于安装成功。 |
| 找不到配置或 `installation.json` | 从保留的源码目录运行 doctor；确认使用原安装 home。不要手写一个新知识目录来掩盖路径错误。 |
| `CORE_DRIFT` 或适配器变更错误 | 先备份并比对本地修改。安装器会保护未知改动；不要为通过检查而删除知识库或整个客户端配置。 |
| 知识目录重叠、路径越界或链接循环 | 知识目录必须与源码目录彼此独立；检查注册路径和符号链接。按实际位置修正配置，不要放宽边界检查。 |
| HTML 没有新笔记或仍是旧样式 | HTML 是快照。确认升级安装成功，再请求 HanOS 用已安装生成器重新生成。 |
| 图谱连接缺失 | 检查文件路径、WikiLink 名称是否唯一。未解析链接会保留；它们不代表笔记被删除。 |
| 模型没有按预期保存 | 确认客户端实际加载了 Skill，保存目的地清楚，并且不是敏感或明确要求不记录的内容。查看源 Markdown，不只看模型的成功描述。 |
| 安装失败并提示 recovery directory | 保留该目录及 `restore-manifest.json`。按映射检查原文件和备份，恢复前关闭客户端；不自动删除失败恢复证据。 |

## 暂时停用

某段内容不想记录时，明确说“这段只聊不记”。要在一段时间内完全停用，使用客户端自己的 Skill 禁用功能；如果客户端没有该功能，可按下方步骤移出相应入口后重启客户端。

同一台电脑可能安装多个适配器。仅停用一个客户端，不要移除其他客户端共用的核心。

## 手动卸载：保留全部知识

当前版本没有 `--uninstall` 命令。以下是完整移除 HanOS 安装入口的流程，不会要求删除知识目录：

1. 关闭会使用 HanOS 的客户端，备份本地 `.config/hanos/`、`.agents/skills/hanos/`、已安装包装目录和需要编辑的客户端规则文件。若使用自定义 `--home`，这些路径都相对于该 home。
2. 阅读 `.config/hanos/install-manifest.json`，确认实际安装的客户端、包装目录及共用核心位置。只处理清单列出的 HanOS 项，未识别的文件先保留。
3. 在 `.codex/AGENTS.md` 中，只移除 `<!-- HANOS_ADAPTER:BEGIN -->` 至 `<!-- HANOS_ADAPTER:END -->` 之间及这两行的托管块。文件其余内容必须保留；若标记缺失或重复，先停止并核对备份。
4. 将清单列出的 Claude Code / Cursor HanOS 包装目录移到备份目录。不要移动整个 `.claude` 或 `.cursor` 目录。
5. 确认所有 HanOS 客户端入口已移除后，将共享 `.agents/skills/hanos/` 和 `.config/hanos/` 移到备份目录。共享路径客户端会随核心移出而停止发现 HanOS。
6. 重新打开客户端，确认 HanOS 不再被发现。你的 `knowledge_home` 中的 Markdown、索引和 HTML 全部保留。

卸载后 doctor 报告未安装是预期结果。需要恢复时，可从备份还原入口，或用源码安装器和原知识目录重新安装。

不要用一条递归删除命令处理整个 home、Agent 配置目录或知识目录。备份确认无误后，再由你决定是否删除旧安装备份。

## 反馈需要什么

通过仓库的 Bug 模板提供 HanOS 版本、系统、Python 和客户端版本、复现步骤、预期结果与实际结果。使用少量虚构笔记复现；不要附真实 HTML、完整工作日志、原生客户端完整执行记录或凭据。

涉及数据外泄或越界读写的问题，按 [SECURITY.md](../SECURITY.md) 走私密报告流程。
